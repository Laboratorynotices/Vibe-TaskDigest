# useAuth

Composable для входа через Google на базе **Netlify Identity** и состояния
текущего пользователя. Собственный OAuth-клиент не используется: редирект и
обмен токена выполняет `@netlify/identity`, сессия хранится в cookie
`nf_jwt`/`nf_refresh`.

## Обзор

Модуль держит общее на вкладку состояние: пользователя, признак выполнения
запроса, текст ошибки и доступность провайдера Google. Все обращения к сервису
входа выполняются только в браузере (`import.meta.client`); при SSR состояние
остаётся пустым, поэтому сессия одного посетителя не может попасть в ответ
другому.

## Состояние

| Имя               | Тип                       | Назначение                                                          |
| ----------------- | ------------------------- | ------------------------------------------------------------------- |
| `user`            | `Ref<User \| null>`        | Текущий пользователь Netlify Identity.                              |
| `pending`         | `Ref<boolean>`             | Выполняется запрос входа/выхода; используется для блокировки кнопок. |
| `error`           | `Ref<string \| null>`      | Текст последней ошибки для live-региона.                            |
| `googleAvailable` | `Ref<boolean \| null>`     | Включён ли провайдер Google; `null` — настройки ещё не загружены.   |

Вычисляемые значения:

- `isAuthenticated` — `true`, если пользователь вошёл (на сервере всегда `false`);
- `displayName` — имя пользователя или «Пользователь». Email намеренно не
  выводится: это служебное поле.

## Функции

### `refreshUser(): Promise<void>`

Перечитывает текущего пользователя через `getUser()`. При ошибке сбрасывает
`user` в `null` и записывает текст в `error`, не выбрасывая исключение.

```ts
const { refreshUser } = useAuth();
await refreshUser();
```

### `loadSettings(): Promise<void>`

Загружает настройки Netlify Identity через `getSettings()` и выставляет
`googleAvailable` по `settings.providers.google`. Список провайдеров не зашит в
код: если Google выключен в дашборде, `googleAvailable` становится `false`, и
панель входа дополнительно поясняет, что провайдер недоступен (сама кнопка
остаётся видимой для проверки). При ошибке вход считается недоступным, причина
попадает в `error`.

### `loginWithGoogle(): void`

Вызывает `oauthLogin("google")` и уводит браузер на страницу Google. Управление
не возвращается; после редиректа страница откроется с токеном в адресе.

### `completeLogin(): Promise<CallbackResult | null>`

Обязательный обработчик возврата после OAuth-редиректа, подтверждения почты и
приглашения. Вызывает `handleAuthCallback()`:

- `result.user` есть — сохраняет пользователя;
- `result === null` (токена в адресе нет) — подхватывает существующую сессию
  через `getUser()`;
- ошибка — пишет текст в `error` и возвращает `null`.

Вызывать один раз при загрузке страницы (в корневом компоненте).

### `signOut(): Promise<void>`

Вызывает `logout()`, удаляет cookie сессии и сбрасывает `user`. Ошибка
записывается в `error`.

## Ошибки

Методы не выбрасывают исключений наружу: текст ошибки попадает в `error`.
Сообщение берётся из `Error.message`, иначе выводится общий текст. Если
Netlify Identity не включён в проекте, `getSettings()` и `getUser()` вернут
ошибку `MissingIdentityError`, она появится в live-регионе панели.

## Ограничения и допущения

- Netlify Identity не работает под `netlify dev`: вход проверяется на deploy
  preview или production.
- Провайдер Google включается только в дашборде Netlify
  (`Project configuration → Identity → External providers`); из кода это не
  настраивается.
- Вход выполняется браузерным редиректом, поэтому SSR-страницы не знают
  пользователя до гидратации. Серверная проверка — отдельно, в
  `server/utils/auth.ts`.
- Сессия общая для вкладок браузера, но не синхронизируется между устройствами.
