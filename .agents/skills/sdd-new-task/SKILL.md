# sdd-new-task

Создаёт файл нового задания в `docs/tasks/backlog/` с автоматической
нумерацией. Отвечает **только** за создание пустого файла и номер; выполнение
заданий — дело Skill `sdd-task-manager`.

## Когда применять

- Пользователь просит создать новое SDD-задание («создай задание на …»,
  «добавь в backlog задачу …», «заведи новую задачу»).
- Нужно узнать или занять следующий свободный номер задания.

Не применять, чтобы выполнить, перенести или отредактировать существующее
задание. Если пользователь просит выполнить задание из `docs/tasks/` —
используется `sdd-task-manager`.

## Как создаётся задание

Из корня проекта выполнить одну команду, передав краткое описание задания
( можно без него — тогда имя будет `NNNN-new-task.md`):

```bash
bun .agents/skills/sdd-new-task/scripts/create-task.ts "добавление генерации PDF-отчётов"
```

Скрипт делает всё сам:

1. Проверяет каталоги `docs/tasks/`, `docs/tasks/backlog/`, `docs/tasks/done/`,
   `docs/tasks/failed/`, `docs/tasks/questions/`.
2. Считает заданиями файлы вида `NNNN-description.md`; `README.md` и файлы без
   номера в начале игнорирует. Задание в любом статусе занимает свой номер.
3. Берёт **максимальный** номер и прибавляет единицу (не количество файлов).
4. Сохраняет принятую в проекте ширину номера, если она одинакова у всех
   заданий; иначе использует минимум четыре цифры с ведущими нулями. Если
   заданий нет — начинает с `0001`.
5. Преобразует описание в slug: нижний регистр, латиница (кириллица
   транслитерируется), цифры и дефисы; пустое описание даёт `new-task`.
6. Создаёт каталог `docs/tasks/backlog/`, если его нет.
7. Создаёт файл **размером 0 байт** эксклюзивно: существующий файл
   перезаписать невозможно. Если имя занято, номера пересчитываются и попытка
   повторяется (до пяти раз).
8. Проверяет, что файл создан и пуст, и печатает путь и номер.

Если скрипт сообщает о неоднозначных именах (например, номер повторяется в
двух файлах или имя не по шаблону), передать эти предупреждения пользователю,
не исправляя чужие файлы.

## Что важно соблюдать

- **Файл остаётся пустым.** Ни заголовков, ни шаблона задания, ни описания:
  даже если пользователь подробно рассказал, о чём задание, этот текст идёт
  только в имя файла. Требования пользователь вписывает сам.
- **Не перезаписывать и не менять** существующие задания и не перемещать
  файлы между каталогами.
- **Не запускать** созданное задание: оно остаётся в `docs/tasks/backlog/`,
  пока пользователь сам не перенесёт его в `docs/tasks/`.
- Не создавать файл в другом каталоге, не менять `README.md` и другие
  документы SDD.
- Не придумывать номер вручную и не создавать файл «на глаз»: единственный
  способ — скрипт, он защищает от перезаписи и повторов.
- Не выполнять коммиты и push без отдельного разрешения.

## Ответ пользователю

Сообщить путь созданного файла, присвоенный номер и что файл пуст и лежит в
backlog. Например:

> Создан пустой файл нового SDD-задания:
> `docs/tasks/backlog/0004-add-pdf-report-generation.md`. Присвоен следующий
> свободный номер: `0004`. Файл находится в backlog и готов к заполнению.

## Проверка

Алгоритм нумерации, построения slug и безопасного создания файла покрыт
тестами: `bun run test --run .agents/skills/sdd-new-task/scripts`.

Полные правила системы заданий — `docs/tasks/README.md` и Skill
`.agents/skills/sdd-task-manager/SKILL.md`.
