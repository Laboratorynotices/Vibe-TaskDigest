# Задания проекта

Здесь живёт очередь заданий, которые выполняет AI-агент. Работа идёт по
принципу **Spec Driven Development (SDD)**: каждое задание — отдельный
Markdown-файл, и этот файл остаётся единственным источником истины о том, что
требовалось, какие были уточнения и что фактически сделано.

Правила выполнения заданий для агента описаны в Skill
`.agents/skills/sdd-task-manager/SKILL.md`; краткий обзор системы — в корневом
[`README.md`](../../README.md), обязательные правила — в
[`AGENTS.md`](../../AGENTS.md).

## Директории

| Директория    | Что лежит                                                          | Кто переносит сюда файл                             |
| ------------- | ------------------------------------------------------------------ | --------------------------------------------------- |
| `backlog/`    | Задания на будущее: сформулированы, но в работу не переданы         | Пользователь                                        |
| `docs/tasks/` | Задания, переданные в работу; только их видит агент                 | Пользователь (из `backlog/`, `failed/`, `questions/`) |
| `done/`       | Выполненные задания, прошедшие все обязательные проверки            | Агент                                               |
| `failed/`     | Задания, где реализация или обязательные проверки завершились неудачно | Агент                                            |
| `questions/`  | Задания, которые нельзя продолжить без ответов пользователя         | Агент                                               |

`README.md` в каждой директории — описание назначения, а не задание: агент их
не выполняет.

## Жизненный цикл

```text
backlog/ ──пользователь переносит──▶ docs/tasks/ ──агент выполняет──▶ done/
                                          │
                                          ├──▶ failed/
                                          └──▶ questions/ ──пользователь
                                                            отвечает и
                                                            переносит файл
                                                            ──▶ docs/tasks/
```

- **Пользователь** создаёт задания, решает, что делать, и переносит выбранный
  файл в `docs/tasks/` — это и есть момент передачи в работу.
- **Агент** обрабатывает только файлы, лежащие непосредственно в
  `docs/tasks/`, и переносит завершённое задание в `done/`, `failed/` или
  `questions/`.
- Из `backlog/` агент задания не берёт никогда: очередь и приоритеты — решение
  пользователя. Задания из `done/`, `failed/` и `questions/` он тоже не
  начинает.

## Формат задания

Один файл — одно задание. Имя: `ID-short-task-name.md`, например
`0008-add-user-authentication.md`; `ID` — четыре цифры, нумерация общая для
всех статусов.

Желательное содержимое файла:

- цель;
- описание требуемых изменений;
- ожидаемый результат;
- ограничения;
- критерии приёмки;
- условия успешного выполнения.

## Правила статусов

- **`done/`** — только если реализация соответствует исходным требованиям, все
  новые и существующие обязательные тесты пройдены, обязательные проверки
  завершились успешно и отчёт дописан в файл задания.
- **`failed/`** — если реализация или обязательные проверки завершились
  неудачно. Отчёт фиксирует проваленные тесты, ошибки и то, что нужно
  исправить.
- **`questions/`** — если продолжение невозможно без информации или решения
  пользователя. Вопросы дописываются в файл, работа останавливается.
- Непроведённая проверка не считается пройденной и сама по себе не даёт права
  на `done/`.

## История

Исходное описание задания не меняется: отчёты, вопросы и ответы дописываются в
конец файла. Предыдущие отчёты и ответы пользователя не удаляются и не
переписываются, поэтому один файл содержит всю историю выполнения, включая
неудачные попытки и повторные запуски.
