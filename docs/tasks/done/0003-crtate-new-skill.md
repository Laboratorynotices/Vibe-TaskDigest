# Задача: Создание Agent Skill для автоматической нумерации и создания новых SDD-заданий

## 1. Цель

Создать новый Agent Skill, который автоматизирует создание файлов новых заданий в системе Spec Driven Development (SDD).

Skill должен самостоятельно определять следующий свободный порядковый номер задания, анализируя уже существующие файлы, и создавать **пустой Markdown-файл** в каталоге `docs/tasks/backlog/`.

Основная цель — избавить пользователя от необходимости вручную искать последний номер задания и самостоятельно формировать имя нового файла.

## 2. Основной сценарий работы

При вызове Skill пользователь может указать краткое название или описание нового задания.

Skill должен:

1. Найти все существующие файлы заданий в проекте.
2. Определить максимальный использованный порядковый номер.
3. Вычислить следующий номер: `MAX_ID + 1`.
4. Сформировать имя нового файла по шаблону:

   `NEXT_ID-description.md`

5. Создать **полностью пустой файл** в каталоге:

   `docs/tasks/backlog/`

6. Сообщить пользователю, какой файл был создан и какой номер ему присвоен.

## 3. Правила определения номера

Skill должен искать номера во всех каталогах, относящихся к системе SDD, а не только в `backlog`.

Необходимо учитывать задания, находящиеся в следующих расположениях:

- `docs/tasks/`
- `docs/tasks/backlog/`
- `docs/tasks/done/`
- `docs/tasks/failed/`
- `docs/tasks/questions/`

При поиске необходимо учитывать файлы с именами, соответствующими шаблону:

`NNNN-description.md`

Где `NNNN` — числовой порядковый идентификатор задания.

Правила:

- Использовать максимальный найденный номер, а не количество файлов.
- Учитывать задания независимо от их текущего статуса.
- Не учитывать README.md и другие файлы, не соответствующие формату задания.
- Поддерживать номера с разным количеством цифр, если они уже встречаются в проекте.
- Новый номер должен быть больше любого найденного номера.
- Если заданий ещё нет, начинать нумерацию с `0001`.
- При формировании имени сохранять принятую в проекте ширину номера, если она однозначно определяется существующими заданиями. В противном случае использовать минимум четыре цифры с ведущими нулями.

## 4. Создание нового файла

Новый файл должен создаваться исключительно в каталоге:

`docs/tasks/backlog/`

Имя файла:

`NEXT_ID-description.md`

Вместо `NEXT_ID` подставляется вычисленный номер.

Если пользователь указал название задания, использовать его в имени файла, преобразовав название в безопасный slug.

Пример:

`docs/tasks/backlog/0012-create-report-generator.md`

Если название не указано, использовать:

`docs/tasks/backlog/0012-new-task.md`

Имя файла должно:

- быть в нижнем регистре;
- содержать латинские буквы, цифры и дефисы;
- не содержать пробелов и специальных символов;
- не приводить к перезаписи существующего файла.

**Важно: создаваемый файл должен быть абсолютно пустым.**

Запрещается автоматически добавлять в него:

- заголовки;
- шаблоны заданий;
- описание задачи;
- разделы;
- комментарии;
- Markdown-разметку;
- любые другие данные.

Создать только пустой файл с правильным именем и расширением `.md`.

## 5. Содержимое нового файла

Новый файл создаётся с нулевым содержимым (0 байт).

Пользователь самостоятельно заполнит его требованиями и описанием будущего задания.

Skill отвечает исключительно за:

1. Определение следующего порядкового номера.
2. Формирование имени файла.
3. Создание пустого файла в `docs/tasks/backlog/`.
4. Подтверждение успешного создания.

Не добавлять содержимое даже в том случае, если пользователь передал описание будущей задачи. Такое описание можно использовать для формирования имени файла, но не записывать внутрь файла.

## 6. Защита от ошибок

Skill должен обеспечивать следующие гарантии:

- Не перезаписывать существующие файлы.
- Не использовать номер, который уже занят другим заданием.
- Не создавать файл, если невозможно достоверно определить следующий номер.
- При обнаружении некорректных или неоднозначных имён файлов сообщать об этом пользователю.
- Перед созданием проверить, что каталог `docs/tasks/backlog/` существует.
- Если каталог отсутствует, создать его в соответствии со структурой SDD.
- Не изменять существующие задания.
- Не перемещать файлы между статусными каталогами.
- Не изменять README и другие документы SDD без необходимости.
- Проверять отсутствие конфликта имени непосредственно перед созданием файла.

Если между определением номера и созданием файла обнаружилось, что выбранное имя уже занято, Skill должен повторно определить максимальный номер и попробовать создать файл со следующим номером.

Для предотвращения перезаписи использовать безопасный способ создания файла, который завершится ошибкой, если файл с таким именем уже существует.

## 7. Создание Agent Skill

Создать отдельный Agent Skill с названием:

`sdd-new-task`

Skill должен соответствовать формату и соглашениям платформы, используемой в проекте.

Перед созданием:

1. Изучить существующие Agent Skills проекта.
2. Изучить структуру и правила SDD.
3. Определить правильное расположение нового Skill.
4. Проверить требования к формату и обнаружению Skills.

Skill должен содержать понятную инструкцию для ИИ-агента:

- когда его следует использовать;
- как находить существующие номера;
- как вычислять следующий номер;
- как формировать имя файла;
- как создавать пустой файл;
- как обрабатывать ошибки и неоднозначности.

## 8. Ожидаемое поведение при вызове

Пример запроса пользователя:

«Создай новое задание на добавление генерации PDF-отчётов».

Ожидаемая последовательность:

1. Skill анализирует все каталоги SDD.
2. Находит максимальный номер, например `0011`.
3. Вычисляет следующий номер `0012`.
4. Формирует имя `0012-add-pdf-report-generation.md`.
5. Создаёт **пустой файл** в `docs/tasks/backlog/`.
6. Проверяет, что файл создан и его размер составляет 0 байт.
7. Сообщает результат.

Пример ответа Skill:

«Создан пустой файл нового SDD-задания: `docs/tasks/backlog/0012-add-pdf-report-generation.md`. Присвоен следующий свободный номер: `0012`. Файл находится в backlog и готов к заполнению».

## 9. Интеграция с существующей системой SDD

Новый Skill должен работать совместно с существующим `sdd-task-manager`, если он уже создан.

При этом:

- `sdd-new-task` отвечает исключительно за создание новых заданий и автоматическую нумерацию.
- `sdd-task-manager` отвечает за управление жизненным циклом заданий и их выполнение.
- Skills не должны дублировать обязанности друг друга.
- Новый Skill не должен автоматически запускать выполнение созданного задания.
- Созданное задание должно оставаться в `docs/tasks/backlog/` до отдельного решения пользователя о передаче его в работу.

## 10. Проверка результата

После реализации необходимо проверить:

1. Skill корректно обнаруживается и доступен ИИ-агенту.
2. Skill находит задания во всех пяти предусмотренных каталогах.
3. Максимальный номер определяется правильно.
4. Следующий номер вычисляется правильно.
5. Новый файл создаётся именно в `docs/tasks/backlog/`.
6. Имя файла соответствует принятому формату.
7. Созданный файл действительно пустой — его размер составляет 0 байт.
8. Существующие файлы не перезаписываются и не изменяются.
9. Повторный вызов Skill создаёт файл со следующим номером.
10. Skill корректно обрабатывает пустой каталог, неоднозначные номера и конфликты имён.

По возможности предусмотреть автоматизированные тесты для проверки алгоритма нумерации и создания файлов.

# Отчёт ИИ-агента

**Дата выполнения:** 2026-11-23

## 1. Выполненные действия

Создан Agent Skill `sdd-new-task` и детерминированный скрипт, который
выполняет всю работу по нумерации и созданию файла. Инструкция Skill лежит в
`.agents/skills/sdd-new-task/SKILL.md` (frontmatter `name: sdd-new-task` +
`description` с триггерами), поэтому Skill обнаруживается по тем же правилам,
что и существующий `sdd-task-manager`.

Созданные файлы:

- `.agents/skills/sdd-new-task/SKILL.md` — инструкция для агента: когда
  применять, какую команду запускать, как обрабатывать предупреждения и что
  сообщать пользователю; прямо запрещает писать что-либо в файл и запускать
  задание.
- `.agents/skills/sdd-new-task/scripts/create-task.ts` — скрипт и
  экспортируемые функции: `parseTaskFileName`, `scanTasks`,
  `determineNumbering`, `slugifyTitle`, `createTaskFile`, `runCreateTask`.
- `.agents/skills/sdd-new-task/scripts/create-task.spec.ts` — 30 тестов
  (позитивные, негативные, граничные случаи).

Изменённые файлы:

- `AGENTS.md` — в разделе SDD добавлен пункт «Создание» со ссылкой на новый
  Skill.
- `README.md` — в разделе «Управление заданиями (SDD)» добавлен абзац о
  создании задания через `sdd-new-task` (строчные окончания CRLF файла
  сохранены).
- `docs/tasks/backlog/README.md` — добавлено упоминание Skill.

Перемещённые файлы:

- `docs/tasks/0003-crtate-new-skill.md` → `docs/tasks/done/`.

Принятые технические решения:

- Логика не оставлена «на усмотрение модели»: нумерация и создание файла
  вынесены в скрипт, который агент запускает одной командой
  `bun .agents/skills/sdd-new-task/scripts/create-task.ts "<описание>"`. Так
  гарантируются одинаковый результат при повторных вызовах и проверяемость
  тестами.
- Номер задания — максимум по всем пяти каталогам SDD плюс один (а не
  количество файлов). Файл считается заданием, если имя начинается с цифр и
  заканчивается `.md`; `README.md` игнорируется. Файл с занятым номером
  учитывается даже при некорректном описании — номер нельзя переиспользовать.
- Ширина номера: если у всех найденных заданий она одинакова, она
  сохраняется; иначе используются минимум четыре цифры. При отсутствии заданий
  — `0001`.
- Slug: нижний регистр, транслитерация кириллицы, только латиница, цифры и
  дефисы, обрезка до 60 символов; пустое описание даёт `new-task`.
- Перезапись исключена: файл открывается эксклюзивно (`openSync(..., "wx")`).
  При `EEXIST` номера пересчитываются и попытка повторяется (до 5 раз). После
  создания проверяется, что размер файла равен 0 байт.
- Описание пользователя используется только в имени файла и никогда не
  записывается в содержимое: создаётся файл размером 0 байт.
- Скрипт не имеет побочных эффектов при импорте: CLI срабатывает только при
  прямом запуске (сравнение `import.meta.url` с `process.argv[1]`), поэтому
  тесты импортируют модуль без создания файлов.
- Тесты работают во временном корне внутри каталога проекта
  (`.tmp-sdd-new-task-*`, удаляется в `afterEach`); за пределы проекта ничего
  не пишется.

  отладочный вывод приложения.
- Совместимость платформ: пути нормализуются к прямым слэшам, ширина номера
  берётся из имени файла, а не из локальных настроек.
