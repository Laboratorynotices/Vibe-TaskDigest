в nuxt.config.ts адрес сайта зашит строкой ( site.url: "https://taskdigest.netlify.app/" ), а не берётся из runtimeConfig

При помощи Nuxt CLI задана переменная NUXT_PUBLIC_APP_URL где и хранится это значение.

В nuxt.config.ts используй эту переменную окружения, а не обычную строку. А так же для теста используй эту переменную окружения где-то в файле app\app.vue

# Отчёт ИИ-агента

**Дата выполнения:** 2026-11-24

## 1. Выполненные действия

Адрес приложения больше не зашит строкой в `nuxt.config.ts`: он читается из
переменной окружения `NUXT_PUBLIC_APP_URL` и используется и для SEO-настроек
(`site.url`), и в публичном `runtimeConfig`, откуда доступен клиенту.

Изменённые файлы:

- `nuxt.config.ts`:
  - добавлена константа уровня модуля `appUrl = process.env.NUXT_PUBLIC_APP_URL`
    с JSDoc-описанием: что это, кто задаёт переменную, где она используется и что
    будет, если она не задана на этапе сборки;
  - добавлена секция `runtimeConfig.public.appUrl` (значение из той же
    переменной, с описанием поля), поэтому клиент получает адрес через
    `useRuntimeConfig().public.appUrl`, а не из захардкоженной строки;
  - в `site.url` вместо строки `"https://taskdigest.netlify.app/"` теперь
    подставляется `appUrl`.
- `app/app.vue`:
  - добавлен `<script setup lang="ts">` с `const appUrl =
    useRuntimeConfig().public.appUrl` и JSDoc-описанием назначения;
  - в шаблон добавлен элемент `<p class="app__url">{{ appUrl }}</p>` (БЭМ-класс,
    без утилит Tailwind в разметке), чтобы значение переменной окружения можно
    было увидеть на странице. Разметка `NuxtRouteAnnouncer` и `NuxtWelcome`
    сохранена.

Принятые технические решения:

- В `nuxt.config.ts` переменная читается через `process.env` на этапе сборки:
  `site.url` из `@nuxtjs/seo` — сборочная настройка, `runtimeConfig` на этом
  этапе ещё не создан. Отдельного резервного значения-строки не добавлялось,
  так как задание требует брать адрес именно из переменной окружения.
- Одно и то же значение попадает и в SEO-конфигурацию, и в
  `runtimeConfig.public.appUrl`; при запуске на Netlify переменная
  `NUXT_PUBLIC_APP_URL` также переопределяет публичное значение рантайма
  штатным механизмом Nuxt.
- Отдельный CSS-файл для БЭМ-блока `app` не создавался: у элемента
  `app__url` нет стилей, а инфраструктуры `assets/styles` (Tailwind, `style.css`)
  в проекте пока нет. Создавать её в рамках этого задания было бы расширением
  объёма.

## 4. Комментарии

- Локально в оболочке `NUXT_PUBLIC_APP_URL` не задана (проверено `printenv`), для
  проверок значение передавалось явно. Переменную нужно задать в настройках
  Netlify (и в локальном окружении для разработки) — реальные значения задаёт
  владелец.
- Значение используется как есть, без нормализации: переменная должна содержать
  абсолютный URL. Прежняя строка заканчивалась слэшем
  (`https://taskdigest.netlify.app/`), поэтому желательно сохранить такой же
  формат значения, иначе возможны склеенные ссылки в sitemap и canonical.
- Если переменная не задана на этапе сборки, `site.url` будет `undefined`:
  приложение соберётся, но SEO-разметке не хватит базового URL (canonical,
  sitemap). На Netlify переменную задаёт владелец в настройках сайта.
- В клиентском статическом бандле (`.output/public`) URL не встречается: Nuxt
  передаёт публичный `runtimeConfig` в HTML при SSR, поэтому это ожидаемо.
- БЭМ-блок `app` пока без CSS-файла: у выводимого элемента нет стилей, а
  Tailwind и `assets/styles/style.css` в проект ещё не подключены. При появлении
  стилей блок нужно оформить по правилам `AGENTS.md`.
- Побочных эффектов нет, несвязанные файлы не менялись.
