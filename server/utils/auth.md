# server/utils/auth

Серверная проверка авторизации на базе **Netlify Identity**. Модуль общий для
всех приватных эндпоинтов `server/api/v1/**`: обработчик не разбирает cookie и
не доверяет идентификатору из запроса, а получает пользователя из сессии.

## Обзор

`getUser()` из `@netlify/identity` читает JWT из cookie `nf_jwt` через рантайм
Netlify Functions и возвращает нормализованного пользователя либо `null`.
Модуль превращает это в обязательную проверку для эндпоинтов.

## Функции

### `requireUser(): Promise<User>`

Возвращает текущего пользователя либо прерывает обработку запроса ошибкой 401.

```ts
// server/api/v1/me.get.ts
export default defineEventHandler(async () => {
  const user = await requireUser();
  return { id: user.id };
});
```

- **Возвращает:** объект `User` из `@netlify/identity` (`id`, `name`,
  `pictureUrl`, `provider`, `roles`, метаданные).
- **Ошибки:** `createError({ statusCode: 401, statusMessage: "Требуется вход" })`,
  если сессии нет.
- **Побочные эффекты:** нет, функция только читает сессию.

## Ограничения и допущения

- Работает только в рантайме Netlify Functions: библиотека берёт cookie из
  `globalThis.Netlify.context`. Вне Netlify (чистый Node, `nuxt dev`) контекста
  нет и `getUser()` вернёт `null`, поэтому проверять вход нужно на deploy
  preview или production.
- Проверка владения ресурсом выполняется отдельно в эндпоинтах, где есть
  загруженная из БД запись: сравнивается `user.id` с владельцем записи. Пока
  слоя БД в проекте нет, такая проверка не реализована.
- Роли берутся из `app_metadata.roles` и попадают в JWT; изменение роли
  действует со следующего входа или обновления токена, а не сразу.
